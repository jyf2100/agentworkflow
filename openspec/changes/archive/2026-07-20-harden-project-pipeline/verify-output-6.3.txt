【canary 目的】
在真实被控仓 cc-web-control 上端到端跑控制面 dev-agent（ADR-0006 vault-only 执行器），
验证 harden-project-pipeline 的运行时模型对真 SDK 成立——这是 ADR-0006 上收后首次
真 SDK 实跑（此前 dev-agent.py 仅 mock-query 单测覆盖）。

【根因 → 修复（canary 第 1/2/3 次失败 → 第 4 次通）】
  run-2：ModuleNotFoundError: claude_agent_sdk —— base python3 无 SDK（cc-web-control
         profile conda_env=None → _env_python 回退裸 python3）。
         修：base python3 装 SDK；部署清单 §1 补 pip install（1.3 clean-env gap）。
  run-3：can_use_tool callback requires streaming mode —— SDK 0.2.123 string-prompt +
         can_use_tool 不兼容。初判为版本回归，钉 0.2.121 仍崩 → 推翻版本假说。
  根因定位：SDK _internal/client.py:103——can_use_tool 回调要求 prompt 为 AsyncIterable
         （streaming 模式）；dev-agent.py 用 string-prompt query()，与 ADR-0006 #7 的
         can_use_tool 回调冲突。ashare 历史 84-turn 成功走的是仓内 dev-agent.py（无
         can_use_tool、2026-07-17、迁移前），非 vault 执行器——vault 执行器从未真跑过。
  修（run-4 前落）：dev-agent.py 把 string prompt 包成单 yield AsyncIterable
         （{type:user,session_id:"",message:{role:user,content:prompt},parent_tool_use_id:None}，
         对齐 SDK 字符串路径 _internal/client.py:214-219）。
         版本钉：pyproject claude-agent-sdk>=0.2.121,<0.2.123；部署清单 §1 钉 ==0.2.121。

【run-4 结果：stalled（exit 12）——内容失败、流水线处理正确】
  dispatch 终态：status=stalled, dev_turns=325, dev_killed=False（非 wall-clock 杀）,
                skip_reason="dev loop 主动刹车（验证红后连续 N 轮无写类进展，exit 12）"
  dev 行为：quota 特性（hub/quota_monitor.cjs + quota_store.cjs + 测试 + hub/server 接入）
           实现后跑测试变红（verify-red，证明 can_use_tool 放行了测试 Bash），LLM 卡在
           "等待子代理测试完成"+ 连发空 user msg 的坏模式（非写类工具）。
  终结：SPEC #27 stall 刹车检测"连续 100 轮无写类进展"→ 干净 exit 12，不 commit/不开 PR。
