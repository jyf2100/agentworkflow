## Why

`verified-dev-execution` today specs only the *mechanical* half of verifying dev output — the executor's hard test-evidence gate (`test_rc=0`) and the truthful JSON result contract. The *semantic* half, `pa-verify` reading the diff + test output to catch "green but off-target" work, has no spec anchor and is driven purely by prompt. Two determinism gaps follow directly from that:

- **Position drift** — `pa-verify`'s `feedback_section` element ① ("location: which file / which test / which assertion line") is free-form text the model composes itself; on large diffs the cited file/line drifts off target, so `dev` cannot act on the feedback reliably.
- **Coverage corner-cutting** — `pa-verify` today "quickly confirms the diff roughly matches the PRD acceptance criteria"; on large diffs the LLM selectively reviews only part of the changeset and misses the rest.

`alibaba/open-code-review` (Apache-2.0; upstream README verified line-by-line 2026-08-04) frames the shared root cause plainly: *"a purely language-driven architecture lacks hard constraints on the review process."* Its remedy is a deterministic-engineering × agent hybrid — independent `comment-positioning` and `comment-reflection` modules, plus `smart file bundling` (divide-and-conquer, isolated per-bundle context). This change ports that philosophy onto `pa-verify` to turn subjective semantic review into anchorable, auditable review — without touching the test gate.

## What Changes

- **Mechanical line anchors for verify feedback.** The orchestrator computes `red test name → pytest failing line number → corresponding diff hunk` with deterministic logic and feeds it to `pa-verify`; the persona only reasons about *why it's red / how to fix*. `feedback_section` element ① changes from free-form text to a structured fragment carrying mechanical anchors.
- **Lightweight reflection on the "how to fix".** Borrow `open-code-review`'s `comment-reflection` idea: the generated fix guidance gets a self-check pass so the content (not just the location) stays on target. Kept lightweight — does not become a separate hard requirement (see design).
- **Bundle-scoped review for large diffs.** When the diff exceeds a threshold, the orchestrator groups related files into bundles (divide-and-conquer, isolated context per bundle) and feeds them to `pa-verify` per-bundle, forcing per-acceptance-criterion coverage instead of a single glance.
- **Deliberate philosophical fork, called out.** `pa-verify`'s pass threshold stays backed by the test gate (high Recall). We explicitly do **not** adopt `open-code-review`'s "precision-over-noise, lower Recall" stance — that would conflict with `verified-dev-execution`'s test-gate semantics. Documented as a fork, not an oversight.
- **Green-path review shape unchanged.** `pa-verify`'s green-path contract (quick-confirm → pass on no major off-target) is preserved: on a large green diff, bundling only splits the glance into per-bundle quick sanity — it does **not** deepen green-path review into exhaustive accounting. The deterministic additions that *do* change behavior (per-criterion coverage accounting, the structured `criteria_coverage` field) act on the **revise path only**. `pa-verify` still only judges, never edits project code / commits / opens PRs (ADR-0002); the test gate remains the hard skeleton.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `verified-dev-execution`: add two requirements covering the currently unspecified *semantic* half of dev-output verification — (1) verify feedback MUST carry mechanically-derived line anchors (location is not free-generated by the model), and (2) large diffs MUST be reviewed bundle-by-bundle to enforce acceptance-criterion coverage. The existing requirements (executor, slug, test-evidence gate, truthful result) are unchanged; these two fill the gap that the spec currently leaves to prompt discretion.

## Impact

- **Control-plane code**: `Projects/项目推进流水线/scripts/run_daily.py` (the `stage_dispatch` verify sub-loop — adds anchor-mapping + bundle-splitting helpers); `Projects/项目推进流水线/scripts/feature_flags.py` (a **new** flag in the existing `LoopFlags` pattern + `FLAGS_ENV_MAP` — `FLAGS_ENV_MAP` is a stable external contract, precedent `cross_prd_learning_*`); `.claude/agents/pa-verify.md` (persona prompt — consume anchors, per-bundle review); `Projects/项目推进流水线/SPEC.md` §4.4 (new input shape) + §4.5 (persona count write-back: 3 → 4, `pa-verify` is already the 4th semantic persona).
- **Target plane**: zero change (ADR-0001/0002 intact). No control-plane/target-plane boundary change.
- **Tests**: new unit tests under `scripts/test_*` — anchor mapping (red test → line → diff hunk), bundle splitting, structured `feedback_section` contract. Hermetic against existing Node/Python fixtures (`reproducible-pipeline-validation`).
- **Dependencies / external services**: none. `open-code-review` is referenced as architectural inspiration only; its CLI is **not** integrated into the pipeline.
- **Test-gate semantics**: unchanged. `test_rc=0` remains the hard pass backbone; the new requirements govern only the semantic review layer above it.
